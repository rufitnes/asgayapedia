# Asgaya Documentation

> Bitcoin Cash remittances with <1% fees, no KYC, self-custody

## What is Asgaya?

Asgaya is a permissionless remittance protocol that enables cross-border money transfers using Bitcoin Cash as settlement layer, with fiat on/off ramps through local payment systems (Bizum in Spain, PagoMóvil in Venezuela).

**Key Innovation:** Two-step settlement with pull-based BCH purchases eliminates volatility risk.

# NotificationListener Documentation

> The "heart of the app" - bridges fiat payment systems and BCH network

## Overview

**NotificationListener** is what makes Asgaya feel magical: payments auto-confirm, no manual steps.

**Three notification systems:**
1. **Bizum** (Spain EUR → Escrow) - Android NotificationListenerService
2. **PagoMóvil** (Venezuela VES → Merchant) - SMS receiver
3. **OP_RETURN** (BCH → All parties) - SPV wallet monitoring

## Critical Review Areas

**1. SMS Spoofing Defense** (`security.md`)

**Claim:** Bank shortcode whitelist prevents SMS spoofing

**Question for reviewers:**
- Can attackers spoof bank shortcodes?
- Is telecom infrastructure security assumption valid?
- What about rooted devices or malicious Xposed modules?

**2. Concept Field Verification** (`README.md`, `security.md`)

**Design:** Recipient phone number in Bizum concept field

**Question for reviewers:**
- Is this sufficient as second factor?
- Can attacker guess recipient phone from transaction ID?
- Should we use something stronger (e.g., BCH address hash)?

**3. Fuzzy Format Detector** (`security.md`)

**Design:** Detect bank notification format changes via pattern similarity

**Question for reviewers:**
- Is Jaccard similarity appropriate metric?
- What false positive rate is acceptable?
- Should we use ML instead of regex + fuzzy matching?
